# 个人报告生成与归档

把用户提供的工作记录整理成正式、可直接汇报的报告，并让聊天中的最终内容与本地 Markdown 文件保持一致。支持三种类型：日报、周报、月报。

## 类型与周期

1. 用户明确说“日报”“周报”或“月报”时按指定类型处理；“今天/昨日”“本周/上周”“本月/上月”等时间词用于确定周期。
2. 用户未指定类型时，依据输入范围判断：单日记录为日报，多日且不超过一周为周报，跨月或按月汇总为月报；无法可靠判断时在输出前说明采用的类型和周期。
3. 日期不完整时不要编造。标题可使用“今日”“本周”或“本月”，文件名使用当前本地日期只在用户明确要求“现在/今天”或未提供周期且需要落盘时采用。

## 整理规则

- 只使用用户提供或已读取到的事实，不补造完成情况、数字、问题或计划。
- 先按项目/模块归类，再合并同一事项的调研、设计、开发、联调、自查和测试记录；避免逐条复制日报造成流水账。
- 保留功能名、配置/协议变化、Bug 或阻塞、验证结果等可追溯信息。问题只在原始记录明确提到时列出；推断的计划必须标注“推断”。
- 用简体中文，措辞正式、简洁。条目较多时使用分级标题、表格或列表。

## 报告结构

### 日报

```markdown
# 日报
**日期**：YYYY-MM-DD

## 今日完成
- [项目/模块] 完成的事项与结果

## 问题 / 风险
- 明确记录的问题、阻塞和待确认项（没有则写“无”或省略）

## 明日计划
- 用户明确提出的下一步；推断内容必须标注“推断”
```

### 周报

沿用 `weekly-report` 的核心规则：用 2–4 句概括主线，按项目/模块合并同类事项，必要时增加“本周产出小结”“风险 / 阻塞”“下周计划”。用户明确要求“三栏”时改为“本周完成 / 遇到的问题 / 下周计划”。

### 月报

```markdown
# 月报
**周期**：YYYY 年 MM 月

## 本月工作概述
2–4 句说明主线、关键产出和验证情况。

## 分项目 / 模块进展
- 按项目归类：完成事项、联调/测试、配置或协议变化

## 问题与风险
- 仅列原始记录明确提到的内容

## 下月计划
- 用户明确提出的计划；推断内容必须标注“推断”
```

## Markdown 归档

最终报告完成后必须同步写入本地文件；文件内容应与聊天中交付的 Markdown 完全一致。

- 根目录固定为 `C:\00work\文档`，类型映射为：日报 → `日报`，周报 → `周报`，月报 → `月报`。目录不存在时创建。
- 默认文件名为：日报 `YYYY-MM-DD.md`，周报 `YYYY-Www.md`（ISO 周），月报 `YYYY-MM.md`。用户明确指定的文件名可在对应目录内使用。
- 推荐使用随附的 `scripts/save_report.py` 写入 UTF-8 文件：先把最终 Markdown 放入临时内容文件，再执行：

  ```powershell
  python <skill-dir>\scripts\save_report.py --type daily --period 2026-08-24 --content-file <draft.md> --overwrite
  ```

  将 `daily` 替换为 `weekly` 或 `monthly`。周报传入日期时脚本会换算 ISO 周；月报传入日期时会取其年月。
- 使用 `--overwrite` 前先检查同周期文件：若它确实是本次报告的旧版本才更新；否则不要静默覆盖，去掉 `--overwrite` 让脚本生成带时间戳的 `-draft-YYYYMMDD-HHMMSS.md`，并在回复中告知实际路径。
- 写入成功后，在最终回复中给出可点击的绝对路径，并说明报告类型和周期；不要只报告“已生成”而不提供文件位置。

## 质量检查

- [ ] 报告类型和周期明确
- [ ] 所有原始记录均已覆盖，没有重复或臆造
- [ ] 项目 / 模块层级清晰，问题和计划没有混入已完成事项
- [ ] 聊天输出与保存的 `.md` 内容一致，文件使用 UTF-8
- [ ] 已确认目标路径在 `C:\00work\文档` 对应目录内
