# 周报生成

将用户提供的日报条目整理为结构化周报。输出语言：**简体中文**。

## 工作流程

1. **解析日报**：逐条读取用户输入（列表、段落、混合格式均可）。
2. **归类合并**：
   - 按项目/模块分组（如 `【征服3职业系统】`、`【官渡之战】`、培训等）。
   - 同类、同方向条目合并为一条，避免重复罗列。
   - 保留关键信息：功能名、联调/Bug、配置/协议变更、自查项。
3. **提炼概述**：用 2–4 句话概括本周主线（不写空话）。
4. **按模板输出**：见 [examples.md](examples.md)。

## 归类规则

| 类型 | 处理方式 |
|------|----------|
| 同一功能点多条日报 | 合并为子项列表或表格一行 |
| 调研 → 设计 → 开发 → 测试 | 按阶段归入同一模块 |
| 自查 / NPE / 多线程 / 持久化 | 归入「质量保障」或「服务端基础」 |
| 客户端修正 | 标注「客户端」或「联调」 |
| 培训 / 会议 | 单独「培训与其他」 |

## 输出要求

- 不编造用户未提及的工作。
- 条目过多时用表格或分级列表，避免流水账。
- 若用户未提供周期，标题写「本周」；若提供了日期范围，写入标题。
- 用户只要简短版时，输出「概述 + 分模块要点」即可，省略「下周计划」。
- 用户明确要求「三栏」（完成 / 问题 / 下周）时，改用三栏模板（见 examples.md）。

## 可选章节

仅在用户需要时添加：

- **本周产出小结**：3–5 条 bullet，适合汇报。
- **下周计划**：留空 checklist 或根据日报隐含待办推断（须标注为推断）。
- **风险 / 阻塞**：仅当日报中明确提到。

## 质量检查

- [ ] 所有日报条目均已覆盖（无遗漏）
- [ ] 无重复叙述
- [ ] 模块层级清晰（项目 → 子模块 → 具体事项）
- [ ] 用语正式、简洁，适合工作汇报
